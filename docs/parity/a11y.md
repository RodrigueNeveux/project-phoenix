# Screen readers (AT-SPI, UIA, NSApplication accessibility)

Phoenix exposes its main views through AccessKit, which GPUI already embeds: `accesskit_unix` (AT-SPI, X11 and
Wayland) in `gpui-pre-linux`, and the AccessKit Windows and macOS adapters on those platforms. A node exists for
every element that has both an `id` and a `role`; labels are set with `aria_label`. Labels are only computed while
an assistive technology is connected (`window.is_a11y_active()`, mirrored in `ui::a11y::on()`), so nothing is paid
when no screen reader runs.

Code: `crates/phoenix-app/src/ui/a11y.rs` (label builders, `Live` wrapper, announcer), call sites in
`server_bar.rs`, `sidebar.rs`, `chat.rs`, `chat/message_ext.rs`, `chat/composer.rs`, `members.rs`,
`title_bar.rs`, `voice_panel.rs`, `app.rs`. Strings: `a11y.*` in `locales/{en,fr}.yml`, mapped to the client's
own translation hashes in `locales/discord.yml` so every client language is served by the runtime table.

## Announcements
The client has two `role=log` regions (assertive, polite). `announce()` adds a new label node in the matching
region each time, so AccessKit emits an AT-SPI `Announcement` even when the same text is repeated.

| Client trigger | Phoenix | |
|---|---|---|
| Toasts (`critical` assertive, others polite) | `parity_toast` | ✅ |
| Message deleted (`RYMs7s`) | delete with and without confirmation | ✅ |
| Reaction added / removed after the API call (`ol4acF`, `DQxi+7`) | `set_reaction_local` on success | ✅ |
| New message that pings me outside the open channel: channel label with its mention count | `MessageCreate` → `announce_mention` | ✅ |
| New messages in the open channel | the client does not announce them (list is not live; reading them is the TTS setting) | ✅ same |

## Focus
Elements with a focus ring (`focus_ring::ring*`) already track a GPUI focus handle; with a role they become the
focused AT-SPI node. The message focused with the arrow keys is reported with `aria_active_descendant` under the
root (`Role::Application`, "Discord").
